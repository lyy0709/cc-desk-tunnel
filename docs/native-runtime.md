# 原生运行与会话存储

本页说明代理如何驱动官方 CLI，以及会话上下文归谁管。只记录代码与对实际进程的检查结果。

## 本体与外层

代理容器承接已认证 WSS、会话索引和原生审批。官方 Agent SDK 的流与 `ccdt` 的 PTY 通过私有 Unix socket 启动运行容器中的官方 CLI。运行容器单独装载应用 home、项目原生工作目录、终端状态、项目工具 socket 和模型提供方设置。Linux Landlock ABI 3 或更新版本限制子进程的文件访问，各次启动使用独立的 Unix 组访问被分配的项目 socket。

GUI 和原生终端通过官方 stdio MCP 配置注册同一个 `project` 服务。本机目录由系统选择器或 CLI 工作目录绑定。项目文件工具使用相对路径，目录和搜索结果按页读取，文本可按字节或行号读取；编辑要求读到的版本和唯一旧片段，显式指定 `all` 时可替换所有匹配，成功后返回新的版本。如果 IDE 同时保存，保留编辑器的版本；需要手动处理的冲突会返回另一份文件的项目相对路径。目录绑定后，同项目会话的命令工具自动可用，命令在本机以当前用户身份执行，逐条审批遵循原生审批模式；长输出通过 `output` 分页读取。输入输出随连接失败的操作视为结果未知。

GUI 通过 Agent SDK 的初始化请求交付项目配置。收到 `mcp_servers_applied: true` 后才发送排队的消息。会话里的项目工具连接状态来自原生 `system/init` 和当前查询的 `mcpServerStatus()`。收到托管策略变更提示后，用户可在会话中刷新状态。[Agent SDK TypeScript 接口](https://code.claude.com/docs/en/agent-sdk/typescript)

项目在设备上的会话提供提问、计划模式、网页搜索、网页读取和待办清单，以及仅访问计划与当前项目记忆目录的内置 Read/Write/Edit。GUI 和终端都检查文件及其父目录，拒绝目录内的符号链接；GUI 的检查使用运行容器记忆目录对应的实际存储路径。检查失败时阻止调用，项目文件与命令仍通过 MCP 执行。在“设置 → 项目工具”里开启后再加上子代理（`Agent`），这是服务端自己的设置，随会话数据保存，默认关闭，从下一次运行或打开终端起生效。子代理从同一组内置工具和会话的 MCP 服务里取工具：在 CLI 2.1.328 上核对过通用、Explore 和 Plan 三种子代理，当时的工具列表只有项目工具和网页工具；新增受限文件工具后同样受文件访问钩子检查，不提供服务器命令工具。Explore 和 Plan 虽然定位为只读，仍能调用项目的写入和命令工具，审批与设备上的命令授权照常适用。每个子代理各自发起模型请求。[子代理](https://code.claude.com/docs/en/sub-agents)

命令授权只对当前设备连接上的会话有效。授权变化通过官方 MCP SDK 的工具列表通知传递，设备在执行前再次核验授权。PNG、JPEG、WebP 和 GIF 按 64 KiB 从设备读取，保留原始编码、尺寸及元数据。单图上限为 20 MiB。[MCP 工具列表变更通知](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)

## 更换项目与换电脑

项目绑定保存在本机，服务端按设备、会话及项目标识路由。绑定目录后自动提供命令工具，设备断开时撤销，重连后恢复。旧会话在项目所在电脑上继续时自动绑定原目录并沿用原生历史；尚未绑定的远程旧会话仍只能查看。

## 上下文的权威

Claude Code 原生存储是模型会话上下文的唯一权威，包含原生消息链、工具结果、压缩记录与原生长期记忆。Linux 普通用户的原生配置目录由 CLI 决定（默认 `~/.claude/`）；本项目不解析和重写 JSONL，不在 Windows 自建上下文管理器，也不用 UI transcript 重新拼历史提示词。

- 每个代理会话绑定同一个 native session ID。Linux cwd 按项目分配：一台设备上的一个项目目录对应 `PROXY_DATA_DIR/native/<root>/`，该项目的会话共用它，如同在本机项目目录里使用 Claude Code，原生的会话历史、自动记忆和项目级设置因此按项目共享。没有项目的普通会话各有自己的文件夹，也就各有一个目录。对应关系记在 `sessions.sqlite` 的 `native_roots` 表里，项目路径按 Windows 不区分大小写、两种分隔符等同的规则比较；会话记下自己的 `nativeRoot`。按项目分配之前建立的会话没有记下它，仍在 `native/<会话 ID>/`，照常恢复，不迁移。
- 首轮 `sessionId`，后续 `resume`；显式 `persistSession: true`。即使每轮启动新 CLI 进程，原生上下文仍由同一 session 恢复。
- 恢复前通过官方 `getSessionInfo` 检查原生记录存在；缺失则明确失败，不静默另开会话，不用代理事件假装恢复。
- 运行结束通过官方接口确认记录已保存，并同步保存状态到 GUI。压缩由 CLI 执行，客户端只展示实际公开的压缩 / 状态事件。
- 每个运行通过专用 Unix socket 访问本次会话的项目工具。设备断开后命令授权失效，在途操作的结果可能未知。重新连接后应先核对项目状态。

工具完整参数会记录到 GUI 事件与历史；旧版本未记录的参数无法补回。可记住的本机命令审批支持“本会话不再询问”，在撤权、设备断线或服务重启后失效；原生强制询问规则仍逐次确认。

代理 `PROXY_DATA_DIR/sessions.sqlite` 只是 GUI 事件、项目绑定、审批偏好与索引的展示镜像；Windows 只有有界会话内容缓存与草稿，打开会话按页拉取，不重放所有 token。镜像里一段输出只存一条；输出途中的片段只转发给正在看的窗口，不落盘。不应把“界面历史存在”当作“原生上下文存在”。

## 登录方式

服务端上的 Claude Code 只有一个登录。图形客户端的运行、ccdt 的终端和读取账号状态的命令，都在运行容器里以同一个个人 home（`/data/home`）启动官方 CLI，读同一份用户设置、全局说明和登录凭据，就像同一个用户在一台机器上同时开几个 Claude Code。会话记录仍在服务端的记录目录里，每次启动只看得到所在项目的那一份。

登录走官方 `claude auth login`。桌面「设置 → 账号与额度」的“普通登录”由服务端在终端里运行这条命令，把它打印的授权链接交给客户端；你在本机浏览器完成授权后，把授权页显示的代码粘贴回来，服务端原样输入给同一条命令。代码的兑换和令牌的保存都由 CLI 自己完成，服务端和客户端不读取、不保存令牌。ccdt 的 `ccdt auth login` 在你自己的终端里运行同一条命令。图形客户端发起的登录和退出要先结束运行与终端；授权链接只发给发起登录的桌面，回调码由该连接交回官方命令。官方命令报告成功后，在没有会话运行时标记首次引导已完成，免得终端再次要求登录。“退出登录”运行官方 `claude auth logout`，同时移除早期版本写进用户设置的 setup token；应用不再生成或粘贴 setup token。

`config/provider.json` 可选：其中的 `ANTHROPIC_API_KEY` 或 Bedrock、Vertex、Foundry 的官方环境变量对所有启动生效，其他设置不传入，账号页会列出它们的名字。保持 `{}` 时使用上面的登录。

额度属于这个账号。图形客户端的运行通过 SDK 读取：回复里的 `rate_limit_event`，以及实验接口 `usage_EXPERIMENTAL_MAY_CHANGE_DO_NOT_RELY_ON_THIS_API_YET({ skipBehaviors: true })`；ccdt 终端的五小时和每周读数取自官方状态栏。两者按官方账号与组织标识记入同一组额度周期。缺少可核实归属的旧记录只进入调用日志。空提供方配置下，定时任务和自动压缩同样使用个人登录。“运行中每分钟读取一次额度”默认开启，关闭后只记录回复和状态栏里自带的读数，手动刷新仍会查询；读取额度不提交模型消息。实验接口可能随官方版本改变，模型专属额度见官方用量页或原版终端 `/usage`。

本项目与 Anthropic 条款的关系见 README 的[账号须知](../README.md#账号须知)。

## 长期保存

使用原生 `cleanupPeriodDays` 管理保留期；本项目为代理拥有的稳定 cwd 写外部 `.claude/settings.local.json`，默认 3650 天，可通过 `CLAUDE_CONTEXT_RETENTION_DAYS` 配置（最低 1）。这不是改写 CLI 或手工清理原生 transcript；其他原生 settings 仍加载，更高优先级配置可能覆盖本值。不能承诺无限保留，磁盘损坏 / 清理也不会因设置而避免。

长线项目应备份 Linux 原生配置目录及代理 state，二者缺一可能损失上下文或索引。Docker 部署将原生 home、state 与工作目录一起持久化，提供停服一致性备份 / 空数据恢复入口，见[部署操作手册](../deploy/README.md)；不自建摘要模型。

应用的 `HOME=/data/app-home`。备份包括应用 home 与原生记录、代理索引、旧 home 和提供方配置。项目 socket、执行连接及会话命令授权只在运行时使用。

会话改名 / 删除先调用官方 `renameSession` / `deleteSession`，成功后更新代理索引 / 展示镜像；运行中禁止管理，原生更新失败保留代理记录。删除不碰 Windows 项目文件。卸载应默认保留原生用户数据，不能误删 `~/.claude/`。

## 默认审批

新会话默认请求原生 `auto`，CLI 自己判断风险；没有本项目第二套 AI 审批器，也不把 auto 换成 bypassPermissions。GUI 可改为原生 `default` / `plan` / `acceptEdits`，偏好保存在 Linux；`bypassPermissions`（绕过权限，什么都不再询问）只在使用者于“设置 → 常规 → 审批”里允许后才出现在选项里，选中前再确认一次，从不作为默认。实际模式读取 `system.init.permissionMode`；版本 / 模型 / 提供方不支持时显示实际值及原生提示。

`canUseTool` 仍接出原生升级到用户的请求，仅作为必要时人工允许 / 拒绝入口；Claude 的提问（`AskUserQuestion`）走同一入口，界面展示问题与选项，用户的选择按官方结构放进 `updatedInput.answers` 返回，不回答则按拒绝返回；不能因默认 auto 就移除或自动允许所有请求。`auto` 下多数操作不需要人工，但这不是所有命令、模型或提供方都不需要人工的保证。

`ExitPlanMode` 的 `plan` 正文在界面中以 Markdown 计划卡片显示，可展开、复制和放大阅读，原始工具详情仍可查看。批准时可选择 `auto/default/acceptEdits`；选择通过 SDK `canUseTool` 的 `updatedPermissions: [{ type: 'setMode', mode, destination: 'session' }]` 返回，由原生退出计划模式并继续同一会话。继续规划则返回拒绝，不更改模式。运行中 `system/status.permissionMode`（包括 `status: null`）作为 `native.permission` 保存并广播，底部显示和后续启动使用原生确认的模式；审批回执本身不代表模式已切换。初始化时的请求 / 实际模式差异继续单独保留。
